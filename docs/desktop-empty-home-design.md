# Desktop 客户端呈现插件：空会话首页设计

状态：首版已实现于 `cqai-dsh-plugin-desktop-presentation`，供 Beta／Stable 的扩展模式和增强模式使用。

## 1. 页面定位

空会话首页是「开始对话」与「选择数字员工」的共同入口。`cqai-dsh-plugin-desktop-presentation` 负责 Desktop 的页面呈现与首页入口编排。配色继续读取现有主题变量；插件的业务页面、启停和安装仍由各自插件及管理能力负责。

设计范围是截图中的主内容区。侧栏、窗口标题栏、现有工作区选择、模式选择、PPT 按钮及原生输入框继续保留。图中的红色框线是布局批注，不代表最终品牌色。

### 卡片内容

| 部位 | 设计 |
| --- | --- |
| 左上 | 统一的单字标记；右上用箭头区分可进入的卡片。 |
| 中间 | 插件名称及一句任务说明。 |

## 3. 内容与排列规则

1. **来源**：首屏含产品已知功能与规划展示位，并合并当前活动 Profile 中提供主面板及侧栏标签的其他插件；插件管理和计划等工具面板不列为数字员工。
2. **展示资格**：动态插件只有在主面板和侧栏入口都已注册时才展示。产品已知功能可以保留未启用占位；纯依赖、账号桥接和后台服务留在插件管理页。
3. **默认顺序**：先显示现有工作台入口，再显示规划中的数字员工；之后以用户保存的顺序为准。新安装的功能追加到末尾。
4. **用户调整**：点击「调整布局」进入编辑态，可通过键盘可用的「前移／后移」排序、隐藏或重新显示卡片。隐藏只影响首页，不会停用或卸载插件；提供「恢复默认」。
5. **保存范围**：布局按当前 Desktop 本地存储中的活动 Profile 名称区分；切换 Profile 后读取该 Profile 的布局。插件暂时不可用时保留其顺序偏好，重新可用后回到原位置。
6. **添加入口**：「添加数字员工」打开现有插件市场／插件管理入口。安装需要重启才能加载时沿用已有提示；首页在插件真正加载后更新。

卡片点击调用 Layout 服务选择已经注册的主面板，不根据包名拼 URL，也不模拟侧栏 DOM 点击。没有注册主面板的展示位不会提供无效的打开按钮。

## 4. 视觉与适配

- **风格**：卡片采用对应员工的全幅封面；没有专属图片时稳定选用三张通用封面。左侧叠加渐变暗遮罩以保证白字可读，标题与操作区沿用主题变量；不沿用手绘稿的红色描边。
- **尺寸**：Logo、首页标题、输入框沿用原组件的尺寸与宽度；桌面宽度下卡片每排三列，列间距约 14 px，单卡高度约 202–220 px。
- **层级**：卡片区显示当前可用数量；可用工作台更醒目，规划项保留清晰文字和状态标识。卡片名约 18 px，说明约 13 px；封面文字在浅色、深色主题下保持清晰。
- **窗口收窄**：根据主内容实际宽度依次变为三列、两列、一列；输入框与模式栏自然换行。页面只让主内容区滚动，不让卡片压住输入框。
- **PPT 模式**：选择 PPT 后，标题、模式栏和 Agent 输入框一起靠上，数字员工卡片收起，让模板列表使用下方空间；退出 PPT 后恢复普通空会话布局。
- **交互**：鼠标悬停仅轻微抬升或变色；键盘焦点清晰可见。编辑态的排序必须有非拖拽操作；遵守减少动态效果设置。

## 5. 接入边界与验收

呈现插件优先在 `dsh-plugin-desktop-beta` 对应的 Beta Profile 中验证，再同步适用于 Stable 的共享部分。它应通过 Desktop 自有组合层和明确的客户端插槽接入，不修改 `deepseek-harness/` 子模块；兼容模式仍使用上游默认客户端。

实现使用 Desktop 自有补丁补充 `conversation.hero.headline`，并让 `conversation.hero.dock` 在所有空白会话中出现；呈现插件只替换标题文字和插入卡片区，原有 Hero 组件、Logo、「预览版」、输入框、工作区与模式控件继续使用。

验收时至少检查：无工作区、空白会话、已有会话切换；浅色／深色和窄窗口；预置与市场插件的真实加载状态；新装、停用、卸载与重启；用户排序、隐藏、恢复与跨 Profile 隔离；卡片入口是否打开正确工作台。
