# e宝工坊插件统一管理界面设计

状态：设计草案，待评审；本文件不代表功能已实现。

## 1. 设计目标

- 左下角账号菜单提供一个 **「e宝工坊插件」** 入口。在同一界面查看随产品提供的功能插件、自行安装的插件，并进入插件市场。
- 清楚区分「当前正在加载」和「下次重启后的选择」。启用、停用、安装、卸载均不暗示即时生效。
- 随产品提供的插件可以停用、重新启用，停用后仍可在列表找到；账号和管理入口所需服务始终可用。
- 保留当前 CQAI 插件市场的搜索、插件详情、安装、已安装管理与来源配置能力。
- DeepSeek 现有插件页的 **「官方 6」** 保持原位置、归属和含义；此界面不修改上游插件页。

首期管理对象是当前运行的 Desktop **活动 Profile**。所有状态和操作都明确标出 Profile；切换 Profile 后重新读取，不能把一个 Profile 的启停选择应用到另一个 Profile。开发版 Beta、安装版和不同 `DSH_HOME` 也应各自隔离。

当前「设置 → 内置插件」是只读的运行清单：卡片上的「已启用」是状态标签，展开后显示配置和运行信息，没有启用／停用操作。上游另有主界面「插件」管理页，但产品默认 bundle 会在 Desktop 启动时自动补入，不能只靠该页修改清单来管理这些产品插件。新管理窗口的「已安装」页必须直接提供可用的启停操作和重启反馈；现有只读清单继续用于查看运行详情。

## 2. 命名与归属

| 页面分组 | 判断依据 | 可用操作 |
| --- | --- | --- |
| 随 e宝工坊提供 | 当前产品版本明确声明的功能插件清单，按精确包名匹配 | 查看详情、启用、停用；不可卸载 |
| 自行安装 | 活动 Profile 中不属于产品清单的直接插件 bundle，包括市场和命令行安装的插件 | 查看状态；按插件能力启停、卸载 |
| 基础服务 | Desktop 壳、CQAI 账号、插件管理入口及其他运行依赖 | 只读说明；无停用或卸载按钮 |

不按 `cqai-` 前缀、插件标题或目录来源猜测归属。市场中安装的 CQAI 插件仍属于「自行安装」；安装来源无法可靠确认时不显示「由市场安装」标签。一个插件只在「已安装」页出现一次。

当前产品功能清单建议固定为以下六项，实际可用性取决于当前版本是否随包提供、以及活动 Profile 是否能解析该包：

| 展示名称 | bundle 包名 | 简短说明 |
| --- | --- | --- |
| e图宝 | `cqai-dsh-plugin-imagegen` | 图片生成与编辑 |
| e剪宝 | `cqai-dsh-plugin-video` | 视频制作 |
| 多平台发布 | `cqai-dsh-plugin-publisher` | 内容编辑与发布 |
| 口播视频制作 | `cqai-dsh-plugin-talkcraft` | 口播与多轨编辑 |
| 短视频制作 | `cqai-dsh-plugin-short-video` | 短视频生成 |
| PPT 制作 | `dsh-ppt-composer` | 演示文稿制作 |

PPT 只管理 Composer bundle；它负责装载的 `dsh-ppt` 核心不作为第二张卡片。口播视频制作与 e剪宝保持独立的任务和数据。以后新增随产品提供的功能插件，需要同时更新产品清单、展示信息和启停策略。

## 3. 入口与页面结构

账号菜单顺序：**打开设置 → e宝工坊插件 → 退出登录**。未登录时仍可打开插件管理；需要账号的插件在自身功能页提示登录。若活动 Profile 没有账号菜单，Desktop 应在设置中提供同一管理入口，保证可恢复停用的插件。

点击后在当前桌面主窗口打开一个管理弹层，复用现有市场弹层的关闭、焦点和键盘行为，不另开 Electron 子窗口。布局参照截图中的「设置」窗口：顶栏横跨整个弹层，**左侧导航从上到下竖着排列，右侧显示当前页面内容**。标题为「e宝工坊插件」，顶栏显示活动 Profile。左侧有两个一级入口：

1. **已安装**（默认）：随产品提供、自行安装、基础服务三个分组。这里完成日常启停和卸载。
2. **插件市场**：保留现有发现、搜索、分类、详情、安装和来源管理。市场原有「已安装」入口跳转到统一的「已安装」页，并定位自行安装分组，避免两份相互矛盾的清单。

左侧导航保持固定宽度，当前项使用与设置窗口一致的选中底色；切换入口时只替换右侧内容，不打开第二层弹窗。示意画面中的状态仅用于说明布局，实际状态必须从活动 Profile 和本次运行结果读取：

左侧的「已安装」「插件市场」始终竖排，不改成顶部横向页签。右侧的插件卡片也逐行纵向排列；名称、用途、状态和主操作保持固定位置。窗口缩窄时右侧卡片内容可换行，左侧导航仍在左边，底部重启提示始终可见。点击卡片进入详情，显示版本、包名、所需账号或依赖、数据位置说明；已加载的插件可在详情中提供「打开功能」或「前往设置」，停用项则提供「启用」。主列表不展示调试字段。搜索只筛选当前「已安装」清单，市场保留自己的搜索框。

「插件市场」使用同一个弹层，不把市场安装的插件混进「随 e宝工坊提供」分组。市场提供浏览、搜索、分类、详情、安装、来源配置；安装完成后返回「已安装」可看到该插件。市场内容不可用时显示原因，已安装页及产品插件启停仍能使用。此方案不改市场 provider 的现有选择方式。

## 4. 启停状态与交互

按钮使用 **「启用／停用」**，表示对下次启动的选择；运行中的插件不会被页面即时卸载。每张卡片同时有「当前状态」和「重启后状态」：

| 当前实际加载 | 已保存的下次选择 | 界面状态 | 主操作 |
| --- | --- | --- | --- |
| 已加载 | 启用 | 当前运行 | 停用 |
| 已加载 | 停用 | 当前运行 · 重启后停用 | 撤销 |
| 未加载 | 停用 | 已停用 | 启用 |
| 未加载 | 启用 | 已停用 · 重启后启用 | 撤销 |
| 未加载且包缺失、损坏或不兼容 | 任意 | 无法加载，并展示原因 | 无启停操作，提供诊断或恢复入口 |

点击「停用」前确认插件名、活动 Profile 和重启影响。若能识别正在执行的任务，显示任务数量；无法识别时也明确说明：**当前任务会继续到重启，重启可能中断未完成任务；已有任务目录和设置不会因停用而删除，恢复能力取决于该插件。** 保存后显示待重启状态。点击「撤销」把下次选择改回本次运行状态，待重启提示随之更新。

底部「立即重启」使用 Desktop 现有的重启能力；在发起重启前再次提醒未完成任务可能中断。重启失败时保留已保存的选择，并显示手动重启指引。重启后只依据实际加载结果更新「当前运行／已停用」；如果启用失败，应显示错误，不能仅因偏好值为启用就显示运行中。停用后侧栏、主区入口及 Host 能力在下一次运行中消失；重新启用后再注册。插件文件、任务、草稿、凭据和历史不因启停被删除。

安装和卸载继续走现有市场的 Profile package 操作与确认流程；产品清单及基础服务不能走市场卸载。自行安装插件的「启用／停用」只在该直接 bundle 可变更时显示。卸载是独立的破坏性操作，不能用「停用」的提示代替卸载确认。

## 5. Profile 与服务边界

当前实现中，默认 `desktop` Profile 会在启动时补齐产品 bundle；仅改界面按钮不足以停用它们。实施时应保留产品 bundle 的安装和声明，使停用项仍可被发现、重新启用；在 **Profile 组合／Loader 生成** 阶段按已保存的选择过滤其 layer 和插件入口。启用前验证包实际存在且 bundle 声明有效。

Desktop 已有 `desktopPlugins` 的清单、预览确认与启停状态文件，可扩展为统一管理能力，但必须处理以下差异：

- 目前 e图宝、e剪宝和多平台发布等产品 bundle 被列为不可变；六个功能插件需要显式可启停白名单。CQAI 账号、插件管理入口、Desktop 壳及上游必要组件继续受保护。
- 当前禁用状态的读取与 `community-market` provider 选择耦合；产品插件的启停必须由 Desktop Profile 独立执行。切换市场 provider 不能让已停用的产品插件重新加载。
- 管理弹层入口应由始终加载的 Desktop 管理组件承载；现有市场插件注册的同名账号菜单动作需要合并，避免出现两个入口。市场 provider 不可用时仍应能重新启用产品插件。
- Host 返回产品清单、活动 Profile、当前运行 generation、实际加载结果和下次选择；Renderer 不直接写 `package.json`、禁用状态文件或执行包管理命令。变更使用受 Profile/generation 约束的一次性确认，提交前复核目标。
- 状态按实际 `DSH_HOME`、桌面发行通道与 Profile 隔离。迁移已有状态时保留用户当前选择；旧版本已在使用的功能插件不因升级被默认为停用。首次引入的新功能由产品清单声明默认值，不从包名前缀推断。

## 6. 实施顺序与验收

先在 `dsh-plugin-desktop-beta/` 完成 Profile 和 Host 能力，再接入账号菜单与管理弹层，复用市场内容；共享改动同步到 `dsh-plugin-desktop/`，保留两版声明的差异。`deepseek-harness/` 上游子模块不承担此产品界面。验收至少覆盖：

1. 登录、未登录和市场不可用时仍能进入管理页；菜单只有一个「e宝工坊插件」入口；「已安装」「插件市场」在左侧竖排且切换后右侧内容正确。
2. 六个随产品功能插件在可用版本中显示，停用后保留在列表且能从「已安装」页重新启用；账号和插件管理入口没有停用按钮。市场或 CLI 安装的插件不计入产品分组。
3. 启停保存后当前运行状态不变，待重启提示和撤销准确；重启后核对 Host layer 与侧栏／主区入口，失败时显示真实错误。
4. 活动任务的重启影响说明、安装／卸载流程、市场搜索与详情、来源配置均可用；启停不删除既有数据。
5. 切换 Profile、`DSH_HOME`、Stable／Beta 后状态不串用；现有「设置 → 内置插件」保持只读，DeepSeek「官方 6」及其页面不变。
6. 通过两版受影响包的测试与 `corepack yarn check:desktop-variants`；最后在全新启动的桌面窗口核对可见界面和实际加载状态。

## 7. 当前代码依据

- `dsh-plugin-desktop-beta/src/profile.ts` 与 `dsh-plugin-desktop/src/profile.ts`：产品 bundle 默认加入 `desktop` Profile、按禁用状态选择 Profile layer。
- `dsh-plugin-desktop-beta/src/desktop-plugins.ts` 与 Stable 对应文件：现有启停预览／执行服务、不可变 bundle 列表和状态存储。
- `deepseek-harness/packages/client/ui-settings-plugin-inventory/src/client/`：当前「内置插件」的只读状态清单；上游源码保持不变。
- `dsh-community-market/src/client/MarketOverlay.tsx`、`MarketSettingsTab.tsx`：现有市场弹层、发现／已安装／来源视图。
- `dsh-community-market/src/client/MarketAccountAction.tsx`：当前账号菜单的市场入口。
- `cqai-dsh-plugins/cqai-dsh-plugin-account/src/client/index.tsx`：账号菜单扩展槽。

本文仅定义目标界面和行为；没有修改上述实现。
