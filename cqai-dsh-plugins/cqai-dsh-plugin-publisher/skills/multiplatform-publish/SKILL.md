# 多平台发布

读取本 Skill 后，当前主对话会在下一步获得所需发布工具。工具只准备内容和确认卡片；提交由用户点击卡片中的确认按钮触发。不能通过终端、浏览器脚本或其他接口替代确认。

## 选择内容来源

- 在发布编辑页的 Agent 抽屉中，调用 `publisher_get_current_draft`。只使用返回的当前草稿，不登记或修改外部 Markdown 原稿。需要继续修改草稿时，读取 `publisher-edit-draft` Skill。
- 在普通对话中，使用工作目录内真实存在的 `.md` 原稿。正文图片使用相对原稿目录的本地路径；绝对图片路径也必须位于当前 Agent 工作目录。仅有上传或生图附件引用时，先将原稿落盘，再用 `publisher_export_image` 保存选中的图片，将返回的相对路径写入原稿。
- 用 `publisher_register_source` 将原稿关联到当前会话，或用 `publisher_get_source` 读取已登记的原稿。修改原稿后重新登记。原稿、图片或修订号失效时先修复来源，不能改用其他对话的内容。
- 只查询任务状态时，直接使用已知的 `request_id` 调用 `publisher_get_publication_status`，无需重新准备内容。

## 准备平台预览

普通对话用原稿最新 `source_revision` 调用 `publisher_prepare_preview`，指定文章或图文、目标平台及必要的平台文案。正文图片沿用原稿返回的 `source-image://` 引用。预览不会提交，也不会复制素材到发布库。

平台标识：`xhs` 小红书、`dy` 抖音、`ks` 快手、`blbl` B站、`tt` 头条、`bjh` 百家号、`juejin` 掘金、`wxmp` 微信公众号、`wx` 视频号。

- 文章候选支持掘金、B站专栏、头条、百家号、微信公众号；图文候选支持小红书、抖音、快手、微信公众号。快手图文可预览，提交能力以工具返回的校验结果为准。头条不提供图文。
- 主稿与平台版本最多引用 20 张不同图片。公众号文章使用 JPEG/PNG 图片与可用封面；原稿中的 WebP 需先转换并更新原稿。公众号图文是图片消息，按图片顺序展示，首图为封面，说明为纯文本。
- 头条文章图片使用文字占位；包含图片或封面时转存平台草稿，用户在后台补图。掘金与B站专栏会移除不支持的正文插图。以预览和确认卡片返回的调整说明为准，不承诺格式或实际发布方式保持原样。

视频使用发布页已有草稿，本 Skill 不剪辑画面或替用户选择本地视频文件。

## 创建确认卡片

调用 `publisher_request_publication`，明确指定来源：

- 当前编辑稿：`source: "current-draft"`，同时传入刚读取的 `content_id`、`binding_token`、`expected_revision`。
- 原稿候选：`source: "prepared-preview"`，传入最新预览返回的 `candidate_id`。

两种来源不能混用。账号、平台和 `mode`（`publish` 或 `draft`）只是建议，由用户在卡片中选择并确认。卡片展示的内容版本锁定；内容变化后重新准备并申请卡片。不要再要求用户跳到发布页重复确认。

返回 `requires_user_confirmation: true` 时，只说明“等待你确认”，不能说已提交。用户取消或没有点击确认时停止提交流程。工具没有确认或提交操作，不能构造一个。

## 核对结果

用户确认后，可用同一 `request_id` 查询状态。`submitted` / `queued` 表示已入队，`running` 表示执行中，只有明确完成结果才报告完成。按返回的实际 `mode` 区分立即发布与保存草稿。失败时说明返回的具体原因；`unknown` / `uncertain` 时请用户核对平台后台，不自动重发。

新的人类输入或本轮结束会卸载执行工具。后续明确发布需求重新读取本 Skill；不要根据历史发布请求自动继续提交。
